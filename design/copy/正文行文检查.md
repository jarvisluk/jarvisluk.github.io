# 正文行文检查（2026-10-16）

范围：项目简介、详情页正文、要点、图注和小尝试的说明文字，共 259 条较长文案。这次只检查，没有改动。标题的问题由另一个会话单独处理，这里不重复。

结论：正文整体能读，问题集中在 7 类“翻译腔”上，共约 40 处，需要改的大约是其中 30 处。每条后面附了建议改法，都只改表达，不改事实。

## 1. 被动句（“被”）照搬英文

中文更习惯用主动句，或者干脆不说出施事者。

| 位置 | 现在 | 建议 |
|---|---|---|
| studies.gocus.graph.body | 提交图是 Gocus 里**最常被看的**部分 | 提交图是 Gocus 里**看得最多的**部分 |
| studies.shokz.player.body | 因为它们常常在同一个时刻**被用到** | 这几样常常是同时要用的 |
| studies.soundbricks.testing.body | 声音也**被忽略** | 声音也没人注意 |
| studies.soundbricks.testing.blocks.1 图注 | 声音**被注意到**，钢琴声最常**被提到** | 孩子注意到了声音，最常提到的是钢琴声 |
| studies.sf-eats.research.body | 让健康的选择更容易**被看见** | 让健康的餐食更容易找到 |
| studies.web-style.agents.body | 会**被检查**，不合法的会**被列出来**退回 | 一样要过校验，不合法的会列出来退回去 |

## 6. 逗号串得太长（英文长句硬拆）

一句话里塞了 4 个以上的分句，读到后面已经忘了主语。建议拆成两三句。

- studies.gocus.library.body：“下面的组件直接取自 0.1.12 的界面，用的是原版 CSS，每张卡片是一个组件，默认、悬停、聚焦……”，建议拆成“下面的组件直接取自 0.1.12 的界面，用的是原版 CSS。每张卡片是一个组件，默认、悬停、聚焦、选中、展开、禁用等状态并排展示，状态样式由原版的 :hover / :focus 规则生成。分段控件和视图切换可以点。”
- studies.web-style.library.body：前半句“锌灰色的底、一种紫色强调色，这个紫色刻意……；浅色和深色……”，建议把“这个紫色刻意不和任何预设的主色撞色”单独成句。
- studies.soundbricks.testing.body：一句话里有 6 个逗号，建议按“第一轮 / 第二轮 / 于是”拆成三句（现在已经大致是这个结构，只需把冒号后的长串改短）。

## 7. Matrix 页面（你刚校对过，先没动）

下面几处有同类问题，要不要改由你决定：

- studies.matrix.experience.body：“这种涌现行为会在矩阵扩展时**被复制**” → “矩阵扩展时，这种涌现会跟着重复出现”
- studies.matrix.control.body：“再由**它**驱动红外传感器……” → “再由树莓派驱动红外传感器……”
- studies.matrix.question.body：“装置想让这种‘涌现’**被看见**” → “这个装置想把‘涌现’做成看得见的东西”
- projects.matrix.approach：“围绕矩阵与涌现概念**进行**结构实验” → “围绕矩阵和涌现做结构实验”

## 不建议改的

- 访谈引语（SoundBricks 老师、FlexBench 学生）保留口语原样，逗号多是正常的说话节奏。
- 图注里“A：B、C、D”的冒号加列表写法，是图注的常见格式，不算翻译腔。
- “这些是设计提案，不是已经落地的运营”这类说明性句子，意思清楚，保持原样。
