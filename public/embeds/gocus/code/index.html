Drawing the graph

Lines and nodes are computed row by row, then painted to a canvas. The graph below runs Gocus’s own geometry and formulas; adjust it directly.

Three commits: the merge at the top puts its second parent on a new lane (the blue line forks right), and the branch commit joins the existing main lane (the blue line curves back). Both bends come from one function with different drop ranges; line widths and node sizes match the app.

How far the bend drops

32–46 px when opening a lane, 28–38 px when joining one, deeper the further apart the lanes are but never past the row; the control points sit 34–48% of the drop away, so both ends meet the rails tangentially.

Lane assignment

Walking newest to oldest, each commit takes the lane already waiting for it, or else the leftmost free one; commits reachable only from other worktrees are drawn dashed.

Detecting the repository

After a folder is opened, Gocus works out which repository it belongs to, whether it is a linked worktree, what is in progress, and when Git’s state changes.

One repository, many worktrees

Agent worktrees all live at different paths; the real path of git-common-dir is the repository’s identity, so in Recent they are one repository.

Finding the real .git

In a linked worktree .git is a file; its gitdir: line and commondir lead to the real directories, whose HEAD, index, MERGE_HEAD and other state files are watched, refreshing 650 ms after they settle.

What is in progress

Merges, rebases, cherry-picks, reverts and bisects each leave a marker file, looked up through rev-parse --git-path so it resolves inside worktrees too; the panel flags the operation and lists conflicted files.

Not a repository, or no Git

Every Git call goes through one entry point with a 10 s timeout and an output cap; a missing git becomes an install hint, and “not a git repository” is classified on its own so the panel shows an empty state, not an error.
